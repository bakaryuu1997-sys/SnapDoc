## 3. Ghi Nhận Điểm Khác Biệt & Lý Do Kỹ Thuật

1. **Định dạng container `.snapdoc` (Task T1 & R6):**
   - Container `.snapdoc` sử dụng chuẩn nén ZIP `CompressionMethod::Stored` (level 0). Để tối ưu hiệu năng và tránh nén kép hao phí CPU, cả hai tệp ảnh `base.png` và `preview.png` bên trong đã được nén compact lossless (PNG Deflate) thông qua `encode_png_compact` trước khi đóng gói vào ZIP. Nhờ đó, file `.snapdoc` vừa nhỏ gọn, vừa tải/ghi cực nhanh.
2. **Native Win32 Clipboard (Task T4 & R3, R4):**
   - Sử dụng Win32 API trực tiếp (`CF_HDROP`, `CF_HTML`, `CF_DIB`) qua crate `windows-sys`. Header `CF_HTML` được tính toán độ dài động bằng format `{:010}` tương ứng đúng 105 bytes thực tế, đảm bảo `StartFragment` và `EndFragment` khớp chính xác từng ký tự `<img ... />`. Đường dẫn URI `file:///` được percent-encode chuẩn RFC 3986 (xử lý trơn tru đường dẫn có dấu tiếng Việt `dự án` hoặc tiếng Nhật `マイドライブ`). Trường hợp API Win32 thất bại, toàn bộ bộ nhớ cấp phát được giải phóng an toàn bằng `GlobalFree`.
3. **Thư viện QR Code Offline (Task T7):**
   - Tích hợp `jsqr` chạy hoàn toàn offline trên Canvas ImageData với guard môi trường an toàn.

## 6. Giới Hạn Đã Biết (Known Limitations)

1. **Dòng văn bản trộn lẫn CJK và tiếng Việt có dấu trong cùng một box đơn:**
   - Trường hợp một từ ngữ hoặc cụm ký tự xuất hiện cả chữ tượng hình Nhật và chữ cái tiếng Việt trong cùng một box (bounding box duy nhất), thuật toán phân loại phát hiện có CJK sẽ giữ kết quả của model CJK (PP-OCRv5) để tránh làm hỏng chữ tượng hình. Điều này có thể khiến một số dấu thanh tiếng Việt trong box đó không được bảo toàn trọn vẹn như khi dùng thuần `rec_vi.onnx`.
2. **Copy nhiều ảnh trên nền tảng macOS:**
   - Cơ chế clipboard hiện tại sử dụng `CF_HDROP` / Win32 API trên Windows. Khi chạy trên macOS, hàm `copy_images_multi` sẽ trả về lỗi `Chưa hỗ trợ trên macOS` an toàn mà không làm sập ứng dụng.
